# Method

New to the terms? Start with [explained.md](explained.md). Results are in [technical-results.md](technical-results.md).

## Question
For a behavioral-economics task with a known human effect, how large is a language model's effect, and does it sit near zero (an "Econ"), near the human value, or beyond it?

## Tasks
Four tasks, each a between-conditions contrast on one outcome (`src/wre/tasks/`):

| Task | Contrast (hi vs lo) | Outcome | Human reference (Many Labs 1) |
|---|---|---|---|
| Framing (Tversky & Kahneman, 1981) | gain vs loss description of the same gamble | chose the certain option (0/1) | d = 0.71 (65.5% vs 34.5%) |
| Sunk cost (Oppenheimer et al., 2009) | ticket paid vs free, bad weather | likelihood of attending, 1 to 9 | d = 0.27 |
| Anchoring (Jacowitz & Kahneman, 1995) | high vs low anchor | numeric estimate (rank-transformed within item) | d = 1.90 (rough: different quantities) |
| Allowed/forbidden (Rugg, 1941) | "allow" vs "forbid" wording | restrictive stance (0/1) | d = 0.76 (23.7% vs 7.2%) |

Each task has one canonical item (a paraphrase of the published task, not verbatim) and 12 freshly written scenarios with the same structure and different surface. Headline results use the fresh scenarios; canonical items are descriptive only. The sources and the estimator conversion for the human values are in `src/wre/human_reference.py`.

## Items
Generated by code from seed 0, frozen in `items/` with SHA-256 hashes. Every prompt in `data/` comes from these sets (`python -m wre.freeze --check` verifies they still match the code). Prompts end with an answer-format instruction ("Answer with only the letter A or B", a number, or yes/no).

Framing items give the same expected value in both frames. In run 3 the certain option is listed first in exactly half of the scenarios in each label format (A/B plans, 1/2 options).

## Effect sizes
Cohen's d, hi minus lo (`src/wre/effects.py`):
- Binary outcomes: log-odds estimator, d = ln(OR) x sqrt(3) / pi, with a continuity correction for sample counts. The same estimator is applied to the human proportions, so models and humans are on one scale. (The Many Labs paper's own d values for framing and allowed/forbidden were computed differently and differ; they are kept in `human_reference.py` as `paper_d`.)
- Continuous outcomes: pooled-SD standardized mean difference.
- Anchoring: estimates are rank-transformed within item, so quantities on different scales are comparable; items where a model gave identical answers in both conditions are kept at zero effect.
- Intervals: item-level cluster bootstrap, 90% intervals, resampling scenarios (the item, not the sampled answer, is the unit of replication). A model that answers identically everywhere has a degenerate interval.
- Econ-ness index: model d / human d (near 0 is Econ, near 1 human-sized, above 1 exaggerated).

## Models and settings
OpenAI via the Responses API (reasoning models, effort set to the lowest accepted setting and recorded per row) or chat completions; Anthropic via the Messages API (effort "low" for Sonnet and Opus; Opus cannot disable thinking). Provider-default sampling. Exact model identifiers, prices and answers per prompt are in `src/wre/models.py`. All data were collected on 2026-11-01.

## Runs
| Run | What | Data |
|---|---|---|
| 1 | 13 OpenAI models, four tasks | `data/run1_openai.jsonl` |
| 2 | 3 Anthropic models, four tasks; OpenAI re-run on revised sunk-cost and allowed/forbidden items | `data/run2_*.jsonl` |
| 3 | Framing robustness: balanced positions x two label formats, all 16 models | `data/run3_*.jsonl` |
| 4 | One-line instructions (`typical`, `gut`, `rational`) on framing and sunk cost, 7 models | `data/run4_prompting.jsonl` |

Each run has a plan with decision rules written before the run (`preregistration/`). The rules are applied by code and each plan's verdict is in `analysis/results/`.

## Response-style checks
A zero or reversed effect can come from always answering one letter or one position, or from saying yes to everything. These are reported next to each effect (`src/wre/diagnostics.py`, `src/wre/robust.py`): letter and position bias (at least 95% of answers on one label), acquiescence for allowed/forbidden (P(yes|allow) + P(yes|forbid) - 1), and parse rates. Cells with under 90% parsed answers are marked invalid, not repaired.

## Spend control
The runner refuses to call an API without `--yes`, enforces a global and per-model dollar cap, and resumes from its JSON-lines output. Cost per call is computed from token counts and the prices in `models.py`.
